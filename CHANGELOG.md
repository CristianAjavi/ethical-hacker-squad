### Added

- **A whole repository with no pointer**: `bench/runs/2026-08-21-whole-repo/`. 286 files, the auditor told only that it was an authorized third-party repository — no module, no file, no hint that a vulnerability existed. It inventoried, routed with `coverage.md`, and reported `CVE-2026-53957` at `exportSpace.ts:134`; a blind judge matched it on mechanism and place. The second target of the same run, a 575-file Python application carrying three advisories, never produced an artifact: its agent was killed five times by the host and was stopped rather than resumed again. That is recorded as an aborted run, not a result.

- **The first measurement on code this project did not write**: `bench/runs/2026-08-21-external/`. **Five** reviewed advisories across three unrelated projects and two ecosystems — `Netflix/lemur`, `contentful/contentful-mcp-server`, `ether/etherpad` — **4 found blind, 1 missed**, with the finding-to-advisory match decided by a context that saw only the advisory text and the finding text and nothing else. Originally three advisories from the GitHub Advisory Database with their upstream fix commits in `Netflix/lemur`; the audited files are the parent of each fix. Two blinded specialists, told only that it was a third-party codebase. **2 of 3 advisories found blind**, 1 missed, 7 further findings that match no published advisory. Those seven are **withheld from this repository** — class and severity only — because they are a third party's possible live defects and publishing their mechanism here would be disclosure by us. The limits are in the run's README with the same weight as the result: the auditors received the affected modules rather than a repository, recall is measured only against advisories that exist, and the comparison between finding and advisory was made by us.

- **The squad audited this repository's own machinery, blinded**: `bench/runs/2026-08-21-self-audit/`. No planted defects, no answer key, no way to score recall — what it measures is precision: **7 findings written, 0 refuted** by an independent verifier told to destroy them (2 verified, 5 partially verified with a named part narrower than claimed). The verifier corrected severity in both directions: two findings inflated, two under-called.

- **The first blinded patch run**: `bench/runs/2026-08-21-patches/`. Two verifiers in fresh contexts, four diffs each, named by id only. **Zero patches accepted that do not fix** — the error that closes a finding while the hole stays open. 6 of 8 exact against the key as authored, 8 of 8 against the key as corrected, and **both scores are published** with the as-authored key stored beside the corrected one, because a key quietly fixed after seeing the answers is not a key. The run corrected the key twice and was right both times: `filter="data"` needs an interpreter this case does not pin, and stripping dashes from a path makes `gpg` sign a different file, which is the finding's own impact surviving the fix.

- **The patch bench**: `bench/patches/`, `bench/patch-truth.json` and `scripts/bench/score-verification.py`. Eight patches over two cases, each claiming to fix a planted defect — one that fixes it, one that looks like a fix and changes nothing, one that fixes it and destroys legitimate input, one that closes the instance and leaves the class. The verifier receives the finding and the diff and returns one outcome per patch; the scorer counts them, and it counts **accepting a patch that does not fix** separately from every other error, because that is the one that closes a finding while the hole stays open. `gate-bench-integrity.sh` now checks that every diff still applies, that each claims a defect the key planted, that each expected verdict is a declared term, that no case has only correct patches, and that no filename hands the verdict away.

- **The bench covers six packs, and the second blinded run scored it**: `bench/runs/2026-08-21-six-packs/`. Four new cases — a Terraform platform with two workflows, a published Node CLI, a RAG support agent with an MCP configuration, and a billing analytics service — bringing the bench to **32 planted defects and 31 decoys**. Six specialists in fresh contexts, artifacts validated before scoring: **32 of 32 detected, 0 of 31 decoys reported**, 8 unlabelled findings the bench never planted and the specialists found anyway. The run also found **six defects in the scoring machinery**, each listed in the run's README with the effect it had on the number — detection moved 26 → 32 and reported decoys 4 → 0 as they were fixed — and none of them touched the stored artifacts, which can be re-scored by anyone.

- **`G6` implemented: `gate-secret-scan.sh`** — ten published secret formats, never entropy, with GitHub tokens settled offline by their CRC32 checksum. Inert markers are excluded so the gate does not fire on `.env.example`. Its second scope is what makes the first honest: `bench/cases/` is skipped because it ships planted secrets, and **every secret-shaped string there is checked against the answer key**, so one nobody planted fails the gate. Git history is not scanned and the gate says so on every run instead of implying the repository is clean back to the first commit. Seven self-test cases, each assembling its token at runtime — a secret scanner that has to skip its own test file is a scanner with a blind spot.

- **The first blinded bench run, and its numbers**: `bench/runs/2026-08-21-blinded/`. Two specialists in fresh contexts, each pointed at a copy of one case with no path to the answer key, emitting artifacts that validated before scoring. **10 of 10 planted defects detected, 0 of 11 decoys reported.** The run also found two defects in the scoring machinery — the scorer matched prose instead of location, and the key named one location for a defect that spans two files — both fixed afterwards, both disclosed in the run's README, and neither touching the audited artifacts, which are stored as written.

- **All eight packs converted to cited triage rules: 154 of 154 procedures**, every pack marked `required`. The conversion is an editorial pass per procedure — `MOB-16` and `MOB-17` cite `FP-10` because their own text says the platform bounds the severity rather than ruling the finding out, and `PRV-01`, `PRV-03`, `PRV-04`, `PRV-07`, `PRV-12`, `INF-05`, `INF-06`, `SUP-21` and `SUP-24` cite `FP-08` because their exculpations live in a data map, an organization policy, a legal obligation or a support subscription that is not in the repository and has to actually arrive. Four procedures — `AI-22` and three `VER-*` — declare `Rules: none (reason)`, a form the gate counts and prints: their class admits no exculpation, and forcing them to cite a rule would have been a lie in a machine-checkable field.

- **`bench/`: the evaluation bench, and the protocol that makes a score mean something.** Two targets written to be read, ten planted defects and **eleven decoys** — constructs that look like findings and are ruled out by a named triage rule, so reporting one is a false positive with an id. `scripts/bench/score.py` reports detected, missed, decoys reported and unlabelled findings, with thresholds opt-in so that a run measures before it judges. `gate-bench-integrity.sh` keeps the answer key honest: a renamed symbol, a deleted case file, a dead procedure id or a case with no decoys all fail. The one rule the protocol turns on: the auditing context must never read the answer key, so the run is a fresh squad pointed only at `bench/cases/<name>`.

- **`findings.json`: the machine-readable half of a deliverable** — `references/findings.schema.json`, `references/findings-artifact.md` and `gate-findings-artifact.sh`. The schema owns the shape and deliberately does not repeat the enumerations: the words come from `vocabulary.md`, the triage rules from `triage.md`, the procedures from `packs.json`. The validator enforces what the shape cannot: `confirmed` demands a complete triage with nothing `UNKNOWN` and nothing `HOLDS`, `probable` names its inferred link, `withdrawn` names its reason, `candidate` never ships, no procedure or identifier is invented, and no high-precision secret format travels inside the file. Ten negative fixtures, each with an `.expected` sidecar naming the defect it stands for, so a fixture that fails for an unrelated reason is itself a failure.

- **`references/triage.md` and `gate-triage-rules.sh`** — the false-positive discipline stops being prose. Ten named rules (`FP-01`..`FP-10`), derived from the 370 exculpation bullets already in the corpus, each answered `HOLDS` / `DOES_NOT_HOLD` / `UNKNOWN` / `NOT_APPLICABLE`, with a reason naming the artifact whenever the answer is not `DOES_NOT_HOLD`. A finding reported `confirmed` has every invoked rule answered, none `HOLDS` and none `UNKNOWN`; `FP-08` exists because "the platform handles it" is the most common way a real finding disappears. The gate enforces the rule set, every citation of it, the answer vocabulary in `team.md` and `report.md`, and per-pack conformance on a ratchet: `web-api` and `local-app` are converted (37 procedures), the rest may only move forwards. The eight auditor contracts now read the rules before writing a finding.
- **`gate-tree-delta.sh`** — the control `gate-plugin-integrity.sh` said was missing. It measures how much a change grows what every user installs, against the merge base: 16 KiB for a `bot/` branch, 64 KiB for a human one, deletions never a failure, and a shallow clone that cannot reach the base is `2`, not a small delta. The absolute cap stays as the outer bound and was re-baselined to 640 KiB with the reasoning written down.
- **`scripts/sync-declared-counts.py`** — the verb that rewrites every count the prose states about the corpus from measurement, so the fix for a `gate-corpus-contract.sh` finding is a command rather than four files edited by hand and a fifth missed.

- **`local-app.md` pack (`LOC-01`..`LOC-15`) and the `ehs-local-app` subagent** — the largest declared coverage gap, closed. CLI tools, desktop shells, published libraries, installers and local daemons had no procedure anywhere, and `coverage.md` routed them to `web-api`, whose own header says not to load it for a library with no network surface. Covers path traversal and archive extraction, symlink following, predictable temporary files, TOCTOU, argument injection (a list instead of a shell string does not stop it), untrusted search paths, configuration discovered from the working directory, permissive file modes, privileged helpers, insecure-by-default library APIs, Electron and WebView renderer isolation, protocol handlers and deep links, local IPC and loopback listeners with no `Origin` check, code arriving at runtime with no verification, and secrets in config, logs and `argv`. Its §0 is what keeps it honest: a local finding must name the second principal and the boundary crossed, or it is a hardening note. The role's contract adds one rule the others do not need — tests create files only inside a temporary directory made for the run, because a symlink or race test pointed at a real path is destruction, not evidence.

### Fixed

- **An unverified cache hit in the tool bootstrap.** The SHA-256 pin was checked at download time and never again, so whatever sat in `$TMPDIR/ehs-gate-tools` — a path any local principal can write on a shared runner — was executed on every later run. The cache is now per-user and `0700`, an install writes a stamp, and a cache that does not match its stamp is ignored and reinstalled. Proved by tampering with the cached binary and watching it be rejected.
- **`python3` module shadowing in the release pipeline.** The verify job runs main's gates with the candidate tree as the working directory, and `python3 -c`, a heredoc on stdin and `python3 -` all put that directory first on `sys.path` — so a `yaml.py` in the candidate would be imported by the gates judging it, defeating "who judges is always main". `PYTHONSAFEPATH` is now set in the release workflow and around the governance helper, which is written to a temporary directory and run by path.
- **The secret scanner was deleting findings.** Its noise filter tested the whole line, so one `https://s3.example.com` in a trailing comment suppressed a live-format key beside it. It now tests the match, with a self-test case that plants exactly that pair.

- **A false green in the gate that exists to stop false greens.** `gate-actions-lint.sh` detected a workflow outside the audited directory, printed `FAIL`, incremented a variable **nothing in the file read**, and exited `0` — so the compensating control that makes the zizmor scope exclusion safe did not fail the build. It now calls `escalate`, the check was lifted out of the block that only runs when the linters bootstrap, and the gate honours `EHS_REPO_ROOT` like every other gate, which is what made a self-test possible at all. Found by a **blinded audit of this repository's own machinery**, not by us.

- **The verification vocabulary had no term for "the patch does not fix it"** — the single most consequential verdict a verifier can return. Its six outcomes covered `verified`, `partially verified`, `refuted` (the *finding* does not hold), and three flavours of not-measured, so a verifier that reproduced the original case after the patch had to write `inconclusive`, which says the run decided nothing. Added `not fixed` to `vocabulary.md` with its neighbour contrasts, and `VER-05` is now seven outcomes. Found by building the patch bench, which is what a bench is for.

- **Identifiers written as prose.** Twenty-six `Traceability` lines across five packs cited ASVS chapters as bare text (`ASVS 5.0 V14, V16`), invisible to every check and to anyone grepping coverage of a chapter. Normalised, and the gate now fails on it.

- **Two holes in the procedure numbering.** `AI-23` and `PRV-12` were drafted in `docs/coverage/` and never landed, so the corpus jumped `AI-22`→`AI-24` and `PRV-11`→`PRV-13` while `team.md` and the packs declared unbroken ranges. Landing them closes both holes; the meter now reports `numbering gaps: none`.
- **A knowledge file that was in no count.** `ai-safety-agent-runtime.md` (`AI-25`..`AI-28`) existed on disk and was not declared in `scripts/meter/packs.json`, so four procedures were invisible to the corpus measurement and the file was missing from the loading map altogether.

- Two identifiers in the landed drafts were corrected before they shipped: ATLAS sub-technique suffixes that could not be verified today were coarsened to the technique that was (`AML.T0010`), and a Microsoft benchmark control was dropped because that source is not in the allowlist. Both are now stated in the citation policy and the gap list rather than left implicit.

- **`plugin.json` no longer declares a fixed `version`.** Claude Code resolves plugin version as `plugin.json` → marketplace entry → commit SHA, so the hardcoded `"1.0.0"` meant that pushing new commits delivered nothing to existing installs: the resolved version never changed and the cached copy was considered current. Every commit on `main` now resolves to a distinct SHA. The semver will live solely in the marketplace entry on the `stable` branch; that branch and its first tagged release do not exist yet.

### Changed

- Repository language is now English throughout, including commit messages. Translating technical material makes it drift away from the identifiers and scanner output it cites. This does not affect report language, which follows the user.
- `SKILL.md` rewritten as a router: safety contract, output language, a load-when table, plugin-agent mapping with a documented fallback, and the leader workflow.
- `coverage.md` rewritten as an inventory-signal routing table pointing at roles and pack sections, rather than a checklist.
- `report.md` now requires a **coverage declaration** naming what was and was not exercised.
- `team.md` now maps each role to its pack and procedure ID range, and requires a coverage declaration from every specialist.
- Standard references updated to the versions verified on 2026-08-04: OWASP Top 10 **2025** (not 2021; SSRF folded into `A01`), LLM Top 10 **2026**, Agentic Top 10 2026, ASVS 5.0.0, MASTG 2.0.0, CWE Top 25 2025, ATT&CK v19, SLSA v1.2, CIS Controls v8.1, CSA CCM v4.1.
