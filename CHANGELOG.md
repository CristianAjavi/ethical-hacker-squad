- **G7 named twenty-one paths and two of them mattered.** The protected-path gate lists every limit an unattributed change touched, so the maintainer can review what the run says is there. Measured across the **28 merged changes that tripped it**: of the 150 paths it named, **38 were fixture inputs** — the `bad/` and `unmeasurable/` files a gate is built to fail on — and on the worst change (`#28`) the **2 genuine limits sat under 19 lines of them**.   The `UNATTRIBUTED` listing now puts the paths that carry weight first and folds negative-proof material into one counted line, grouped at the level the pattern names (`fixtures/negative-proof/bad (9)`), stating what watches it. On `#28`'s real diff that is **21 lines down to 8**. Folding is a display decision and **nothing is exempt**: when G7 *fails*, and when a maintainer waves a marked change through with `override/g7-reviewed`, every path is named in full. A `.expected` assertion never folds — the input is the proof, the assertion is what says the proof proved anything, and nothing else watches an assertion being weakened. Seven new self-test cases (25 total), each shown load-bearing by a mutant: fold a finding and `a-finding-names-every-folded-path-in-full` goes red; drop the `except` and the `.expected` case goes red; drop the counted line and two more go red.

- **The leader has been ordered to deduplicate findings since this corpus existed, with no criterion, no check and no trace.** `references/team.md` says it in three separate places. `references/triage.md` governed only the other way a finding stops being reported — the ten `FP-*` rules that rule one out — and the artifact recorded a merge in exactly one spot: `engagement.unaided_pass.dropped[].resolution: merged`, which covers a candidate absorbed inside **one specialist's own pass**.   **`DUP-01`..`DUP-06`, in their own marked region of `triage.md`.** Six separating conditions, answered with the same four answers as the FP rules, any one of which holding means the two findings are two: one source with two sinks; two sources with one sink; the same class at two lines of one file; two sides of different trust boundaries; caller and callee where **the callee has other callers**, decided by counting them rather than by eye; and the same defect behind two different reachability preconditions. The test they serve is not similarity — it is **whether one fix closes both**, because the reader of a report is somebody who is going to repair something and a merge is a promise that one repair discharges the entry.

  **The two errors do not cost the same, so the default is asymmetric.** A wrong merge deletes a finding; a missed merge lengthens the report. An `UNKNOWN` answer therefore resolves to `possible_duplicate_of` — both findings ship, both are counted, the pair is named — and never to a merge. `duplicate_of` requires `merge_rules` with every rule answered and none holding, and the absorbed finding **keeps its id in the artifact**: it is rendered under its parent, not deleted.

  Invariant 10 of `findings-artifact.md` enforces all of it — the target exists, is not the finding itself, is not itself a duplicate (no chains), and no id is named as both a merge and an undecided pair. - **The control that forbids an automation from editing its own limits was asking the automation whether it was one.** `gate-protected-paths.sh` is G7: it guards `scripts/gates/**`, `docs/gate-requirements.md`, `skills/**/SKILL.md`, `.claude-plugin/**`, `agents/**`, `.github/workflows/**`, `LICENSE` and `NOTICE.md` — the paths that define what this system may do and what it may read. The agent had chosen that name. Replaying that exact diff through the gate as it stood returns `0`; through the gate as it now stands, `1`, naming the trailer that caught it.

  **The fix is not a longer prefix list**; every list of chosen names has the same hole. It is that a self-declaration is worth something in exactly one direction — **an admission incriminates, a denial exculpates nothing** — so the prefix stays, demoted from *the* classifier to one signal among several, and it is joined by the marks an agent's harness writes into the **commit range** rather than into a name: a `Claude-Session:` trailer, an `@anthropic.com` or `[bot]` identity, both lists now in `protected-paths.json`. Measured on the four commits merged as PR #72: all four carry the trailer. The mark can be stripped, and then the gate is back where it started — but stripping it is an act, where picking a branch name was not even a decision.

  **Nothing is called a human change any more.** Nothing available when this gate runs proves a person made a change: a pull-request approval does not exist yet when CI fires, and every other signal is written by the editor. So the third state is written down as what it is — `UNATTRIBUTED`, allowed and listed, never described as something it was not — and in a single-maintainer repository the separation stops there **on purpose and in writing**, because the maintainer and the maintainer's agent commit with the same account and the same email. The property this now guarantees is not *an automation cannot move a limit*; it is **an automation cannot move a limit unnoticed**, which is the one that was missing. **Blindness is not innocence either**: with the commit range unreadable and a protected path in the diff the verdict is `2`, because half the classifier did not run and the diff is in the half that matters — while a diff that moves no limit stays `0`, since a gate that goes amber on every ordinary pull request is a gate people learn to skip.

  **The way out is a label**, `override/g7-reviewed`, chosen because it is the one signal that does not live in the change at all: not in the branch, not in a commit, not in the changed files. Granting one is a separate act on GitHub, visible in the pull-request timeline, rather than a line in the diff that grants it. `labeled`/`unlabeled` became trigger types, since a label that does not re-run the gate is not an override, and the workflow resolves its presence to **one of two literals** before anything reaches a shell — the label list is untrusted content and never crosses that boundary. Using it prints every path that moved, in capitals, *with consent*: an override that reads like a pass is a pass. It does not silence the drift check, and standing on a change with no automation mark it is called out as worth removing. **The battery went from 10 cases to 18**, with the commit range and the label injected by the harness rather than read from git — a battery that reads the same signal from the same place as the gate is testing nothing. **And the override's own limits are written down instead of discovered.** The label is out of reach of the branch, the diff and the workflow token — but not of an agent holding the maintainer's `gh` credentials, which to GitHub *is* the maintainer; the honest boundary of G7 is the CI surface. This pull request was left to fail its own gate rather than wave itself through, which it could do because the protected-paths job is **not** among `main`'s required checks. Whether it should become one is the open question the fix hands back: a gate key an automation can turn is not a key.

### Fixed

- **An unverified cache hit in the tool bootstrap.** The SHA-256 pin was checked at download time and never again, so whatever sat in `$TMPDIR/ehs-gate-tools` — a path any local principal can write on a shared runner — was executed on every later run. The cache is now per-user and `0700`, an install writes a stamp, and a cache that does not match its stamp is ignored and reinstalled. Proved by tampering with the cached binary and watching it be rejected.
- **`python3` module shadowing in the release pipeline.** The verify job runs main's gates with the candidate tree as the working directory, and `python3 -c`, a heredoc on stdin and `python3 -` all put that directory first on `sys.path` — so a `yaml.py` in the candidate would be imported by the gates judging it, defeating "who judges is always main". `PYTHONSAFEPATH` is now set in the release workflow and around the governance helper, which is written to a temporary directory and run by path.
- **The secret scanner was deleting findings.** Its noise filter tested the whole line, so one `https://s3.example.com` in a trailing comment suppressed a live-format key beside it. It now tests the match, with a self-test case that plants exactly that pair.

- **A false green in the gate that exists to stop false greens.** `gate-actions-lint.sh` detected a workflow outside the audited directory, printed `FAIL`, incremented a variable **nothing in the file read**, and exited `0` — so the compensating control that makes the zizmor scope exclusion safe did not fail the build. It now calls `escalate`, the check was lifted out of the block that only runs when the linters bootstrap, and the gate honours `EHS_REPO_ROOT` like every other gate, which is what made a self-test possible at all. Found by a **blinded audit of this repository's own machinery**, not by us.

- **The verification vocabulary had no term for "the patch does not fix it"** — the single most consequential verdict a verifier can return. Its six outcomes covered `verified`, `partially verified`, `refuted` (the *finding* does not hold), and three flavours of not-measured, so a verifier that reproduced the original case after the patch had to write `inconclusive`, which says the run decided nothing. Added `not fixed` to `vocabulary.md` with its neighbour contrasts, and `VER-05` is now seven outcomes. Found by building the patch bench, which is what a bench is for.

- **Identifiers written as prose.** Twenty-six `Traceability` lines across five packs cited ASVS chapters as bare text (`ASVS 5.0 V14, V16`), invisible to every check and to anyone grepping coverage of a chapter. Normalised, and the gate now fails on it.

- **Two holes in the procedure numbering.** `AI-23` and `PRV-12` were drafted in `docs/coverage/` and never landed, so the corpus jumped `AI-22`→`AI-24` and `PRV-11`→`PRV-13` while `team.md` and the packs declared unbroken ranges. Landing them closes both holes; the meter now reports `numbering gaps: none`.
- **A knowledge file that was in no count.** `ai-safety-agent-runtime.md` (`AI-25`..`AI-28`) existed on disk and was not declared in `scripts/meter/packs.json`, so four procedures were invisible to the corpus measurement and the file was missing from the loading map altogether.
