# One list of secret formats for every check that refuses an unredacted secret:
# scripts/gates/lib/findings_artifact.py (findings.json), scripts/ehs.py sarif
# (the export that gets uploaded) and scripts/gates/gate-report-contract.sh
# (report.md and the served tree). Until 2026-10-15 each had its own list, and
# the two narrowest guarded the two files that leave the machine.
# scripts/gates/lib/secret_scan.py (G6, which scans this repository with its
# bench exclusions) still keeps its own list; it is not wired to this file yet.
#
# Four TAB-separated columns: id, prefix, regex, note. The extension is .txt on
# purpose: run-all.sh treats any file under scripts/gates/ it does not know as a gate.
#   prefix - an interval-free ERE anchored with ^, used by awk to classify a hit
#            (the awk shipped with macOS and mawk disagree on {n,m});
#   regex  - the full format, valid both as a POSIX ERE (grep -E) and as a
#            Python `re` pattern. Every regex is length-gated, so a bare prefix
#            in prose that TEACHES the format never matches; only a value does.
# A redaction that keeps the prefix and drops the body ("sk_live_[REDACTED:secret]")
# stays silent by construction.
#
# Prefixes checked on 2026-10-15 against the vendors' own documentation and the
# gitleaks default rules (config/gitleaks.toml at 09242ce9c8a6), which has no
# rule for sb_secret_ or whsec_; GitHub secret scanning covers both.
github-token	^gh[pousr]_	gh[pousr]_[A-Za-z0-9]{30,}	GitHub token; a classic one is 40 chars with a CRC32 checksum verifiable offline, and a shorter body is still a token-shaped value no deliverable needs
github-pat-fine	^github_pat_	github_pat_[A-Za-z0-9_]{60,}	fine-grained GitHub PAT
aws-access-key-id	^(A3T|AKIA|ASIA|ABIA|ACCA|AROA|AIDA)	(A3T[A-Z0-9]|AKIA|ASIA|ABIA|ACCA|AROA|AIDA)[A-Z0-9]{16}	AWS access key id (AKIA) or temporary STS key (ASIA); prefixes per the gitleaks default rules
anthropic-key	^sk-ant-	sk-ant-[A-Za-z0-9_-]{24,}	Anthropic API or admin key
openai-key	^sk-	sk-(proj-|svcacct-|admin-)?[A-Za-z0-9_-]{32,}	OpenAI API key: project, service-account, admin or legacy
slack-token	^(xox|xapp-)	(xox[baprse]|xapp)-[A-Za-z0-9-]{16,}	Slack bot, user, refresh or app-level token
google-api-key	^AIza	AIza[A-Za-z0-9_-]{35}	Google API key; a Firebase web key is public by design, a Gemini key on the same format is not, and a deliverable needs neither in full
stripe-secret-key	^(sk|rk)_(live|test|prod|org)_	(sk|rk)_(live|test|prod|org)_[A-Za-z0-9]{16,}	Stripe secret, restricted or organization key. Clerk secret keys share the sk_live_/sk_test_ prefix; both are secrets
stripe-webhook-secret	^whsec_	whsec_[A-Za-z0-9+/=]{24,}	Stripe webhook signing secret
supabase-secret-key	^sb_secret_	sb_secret_[A-Za-z0-9_-]{16,}	Supabase secret API key; bypasses every row-level security policy. Body length is not published, hence the conservative gate
gitlab-pat	^glpat-	glpat-[A-Za-z0-9_-]{20}	GitLab personal access token
npm-token	^npm_	npm_[A-Za-z0-9]{36}	npm automation token
pypi-token	^pypi-	pypi-AgEIcHlwaS5vcmc[A-Za-z0-9_-]{50,}	PyPI API token
sendgrid-key	^SG\.	SG\.[A-Za-z0-9_-]{22}\.[A-Za-z0-9_-]{43}	SendGrid API key
private-key-block	^-----BEGIN	-----BEGIN [A-Z ]*PRIVATE KEY-----	PEM private key header
signed-jwt	^eyJ	eyJ[A-Za-z0-9_-]{8,}\.eyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{16,}	signed JWT; a Supabase service_role or secret JWT bypasses row-level security, and an anon one has no business in a deliverable either. The third segment must be present, so an alg:none teaching example does not match
