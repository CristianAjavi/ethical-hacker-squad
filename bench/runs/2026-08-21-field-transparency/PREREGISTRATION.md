# Pre-registration — what the field publishes about itself

**The rubric below is fixed before a single competing product is opened.** If it is tuned after looking, the result is worthless, and this file is what makes that checkable.

## Why this dimension and not another

Eighteen measurements say detection is the model's. Three arms, seventy-one claims, and the only true findings any of them produced were the two the ground truth already named. No intervention moved it: a loading rule repaired damage this project had introduced, an artifact contract never reached the reviewer's behaviour, and a critic stage bought the best precision in the bench by deleting a true defect from every run.

If capability is the model's, then what separates products is **what they let you check** — and that is entirely the product's, not the model's.

## The rubric, fixed now

For each product, six binary questions, answered only from what the project itself publishes. No inference, no benefit of the doubt, and a link or a file path for every `yes`.

1. **A measured detection number** — any published figure for what it finds, on any target, by any method.
2. **The method behind that number** — enough that someone else could re-run it: target, arms, scoring rule.
3. **A comparison against not using it** — the product measured against the same model working without it.
4. **At least one published negative result** — a case where the product did no better, or worse.
5. **A retraction or correction** — a published number later withdrawn or amended.
6. **Pre-registration** — a prediction and its refutation criterion recorded before the result existed.

## Scope, fixed now

The products are the five named in this repository's existing competitive analysis, plus `google/mantis`, which is the arm already in the bench. **No product may be added or dropped after the survey starts.** If a name in that analysis no longer resolves, it is recorded as unreachable, not replaced.

## The prediction

**Prediction: this project answers `yes` to all six; no other product answers `yes` to more than two; and at least one answers `yes` to none.**

**What refutes it:** any product matching this project on four or more, or this project failing any of the six against its own repository.

## What each outcome forces

- **Prediction holds** — then on evidentiary transparency, which is a real dimension and entirely the product's, this project leads the field. That is a **narrow** claim: it says nothing about finding more bugs, and the eighteen measurements saying the corpus leads on nothing stay exactly where they are, unchanged and above the pitch in the README.
- **Prediction fails** — then this project is not best on the one dimension where it looked most likely, and the README says so with the same prominence.

## The caveat that travels with any result

**Publishing your own failures is not the same as being good.** A product that measures nothing and works well beats one that measures everything and does not. This round measures what a buyer can *check*, and that is worth exactly what checkability is worth — no more.
