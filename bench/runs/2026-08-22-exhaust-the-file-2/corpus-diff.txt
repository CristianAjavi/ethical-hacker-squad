< ## When a file earns a reading, it earns a full one
< 
< **Do not leave a file you opened for a reason after the first defect you find in it.**
< 
< A file you reached deliberately — because the inventory pointed at it, because it plainly handles input from outside — rarely has exactly one thing wrong. Finding the first is the moment you are most likely to stop, and stopping there is how a review misses the defect beside the one it reported.
< 
< Before you leave such a file: **list every distinct route by which untrusted input reaches code in it**, and account for each route. A route is a finding, or it is safe and you can name the line that makes it safe. A route you never listed is neither.
< 
< This is not a class of defect and it is not tied to any stack. It is the difference between *I found a bug here* and *I know what this file does with what it is given.*
< 
< Measured, and it is why this exists: on two whole repositories with no pointer, two independent reviews each reached the correct file, read it, and each reported a real defect in it — and each missed a different published defect a few lines away. Neither had a rule that said to keep going. `bench/runs/2026-08-22-routing-at-N/`.
